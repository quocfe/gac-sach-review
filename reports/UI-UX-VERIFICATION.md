# Gác Sách — UI/UX redesign verification

## Outcome

Warm paper / forest-green / terracotta editorial system, serif reading hierarchy, typographic covers explicitly marked as illustrations, shared header/footer, mobile navigation, keyboard focus/skip link, reduced-motion support, responsive catalog/detail/composer/shelf/admin screens.

The public browsing surface is **Explore**. The composer is **Configure** and moderation is **Operate**: their forms and actions take priority over decoration. Design self-audit: 0/10 of the design skill's generic-template tells; no generic feature-tile hero, glass blur, fabricated usage stats, or unrelated tech gradients. This is a qualitative review, not a user-research result.

## Interaction regression coverage

- Search by unaccented Vietnamese title/author and ISBN; combined query + genre preserved through submission, reload, clear and browser history.
- Repeated query parameters no longer crash the catalog; first value is used.
- Empty search state and reset; unknown book/review route has a useful 404 recovery link.
- Mobile menu open/close, current destination, Escape and returned focus.
- Local rating and bookshelf survive reload without hydration mismatch.
- Editor draft/title/body/spoiler/edition restore; preview treats HTML as plain text; clearing the draft persists; malformed/blocked local storage does not crash writing.
- Composer does not claim a nonexistent submission; admin's unimplemented controls are disabled with explanation.
- Mobile book actions precede secondary editions/reviews.
- Report/moderation network errors keep user notes and show retry guidance; moderation's real demo endpoint response is rendered in its session audit view.

Tests were introduced and observed failing before the corresponding catalog, composer, navigation/storage, 404, mobile ordering and report-error fixes. Existing behavior was additionally covered by search/blocked-storage/moderation regression assertions.

## Honest limits / deliberately unchanged

- No real authentication, user roles, durable review publishing, catalog editing or import pipeline was added. API/domain/service modules are unchanged.
- Rating, bookshelf and drafts remain local to one browser. Draft submission is now explicitly unavailable instead of deleting a draft and falsely claiming it entered moderation.
- Books, ISBNs, scores and review counts remain sample data. Typographic covers are not publisher artwork. Fictitious rating/ISBN JSON-LD was removed from detail pages rather than publishing demo values as facts.
- Moderation/report endpoints retain their existing in-memory demo semantics and client-supplied demo actor. The UI discloses this, but it is not production authorization. The moderation endpoint still returns `from: pending` for its independent demo transitions; UI does not invent a corrected server history.
- No remote push, deployment, live data migration, cross-browser audit, screen-reader audit or new Lighthouse run was performed.

## Reusable implementation notes

1. Resolve App Router `searchParams` on the server; handle `string[]` explicitly. A native GET form is sufficient for shareable, keyboard-friendly catalog filtering and history without racing client state.
2. Restore browser storage after hydration. Validate JSON shape, catch blocked/quota storage, and save empty values as well as non-empty values; otherwise deleted draft text can reappear.
3. A successful simulated action must never imply an implemented backend. Disable unavailable operations and describe local/session/in-memory persistence where the action appears.
4. Use real failure/recovery tests, not only page screenshots. A screenshot cannot prove draft retention, filter history, or server error handling.
5. In this environment Turbopack dev repeatedly refreshed the page even without source edits. The Playwright dev server uses `--webpack` as a scoped test-harness workaround. The release gate uses the actual Turbopack production build with `E2E_PRODUCTION=1`; no Next application config was changed.
